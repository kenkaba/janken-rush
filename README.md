# JANKEN RUSH — prototype v0.1

ジャンケンの皮をかぶった「期待感エンジン」。
単一HTMLファイル（`index.html`）。依存ライブラリ・画像・音源ファイルはゼロ。

```bash
python3 -m http.server 5177 --directory .
```

---

## 設計の芯

このゲームの主役は**勝敗ではなく、結果が出るまでの時間**。
気持ちよさは「勝った瞬間」ではなく「勝ちそうな瞬間」に発生する。したがって全設計は次の3点に従う。

1. 結果が確定していない時間をどれだけ引き伸ばせるか
2. その時間中に希望を何段階に分解できるか
3. 裏切りと復活をどこに置くか

### 勝敗は演出より先に決まっている

`planRound()` がプレイヤーの入力より前に「勝敗・期待度tier・演出ルート」を決定する。
プレイヤーの手が決まった後に、その結果になる敵の手を逆算して出す。

これはジャンケンとしては不誠実に見えるが、パチンコ的高揚感の必須条件である。
出目が先に決まっていなければ「演出で結果を予告する」ことができず、期待感が成立しない。

**ただし「読み」を完全に無意味にはしない。** 敵は毎回セリフで手の傾向を漏らす。
その弱点を突くと勝率ではなく**演出期待度が1段上がる**（`読み勝ち！`）。
プレイヤーの上手さは「勝つこと」ではなく「アツい演出を引くこと」に接続される。

### 期待度の階段（6段）

`なし → シアン → 緑 → 赤(激アツ) → 金(超激アツ) → 虹(確定)`

同じ色を、先読みオーラ・目の発光・カウントダウンの色と音程・上部の期待度メーターの
4箇所で同時に表現する。プレイヤーは説明なしに色の序列を学習する。

### 演出ルート

| ルート | 役割 |
|---|---|
| 先読み | 手を選ぶ**前**に敵の目が光る。選択そのものを賭けにする |
| 擬似連 | あいこ→「まだ終わらない」→再抽選。1回の勝負を最大4回に引き伸ばす |
| カットイン / 役物落下 | 決着直前の格上げ。tierが高いほど出やすい |
| 復活 | 一度LOSEを見せてから覆す。最大の脳汁ポイント |
| フリーズ | 画面と音を1.5秒完全停止 → 虹 → 勝利確定。最上位 |

### 勝率カーブ

序盤2回は**必勝**。初回プレイで演出を1つも見ないまま終わると「もう一回」が生まれないため。
以降はステージが上がるほど落ちにくくする（登るほど手放したくなくなる）。

20,000回シミュレーションの結果:

| 指標 | 値 |
|---|---|
| 中央値 | 4連勝 |
| 兆しステージ到達 | 78.1% |
| RUSHステージ到達 | 37.3% |
| 神域ステージ到達 | 12.2% |
| 超神域ステージ到達 | 5.8% |

ほぼ全員が初回でステージ進化を体験し、神域は「他人に言いたくなる」希少度に収まる。

### リザルトの後悔設計

ゲームオーバー画面は戦績ではなく**「あと2連勝で神域ステージだった」**を主役にする。
再挑戦動機は達成感より未達成感から生まれる。

## 実装上の判断

- **Reactを使わない。** 演出ゲームはフレーム単位で状態を殴る必要があり、再レンダ思想と相性が悪い。
- **音は全てWebAudioで合成。** 音源ファイル0バイト。確定音は10音の高速上昇アルペジオ。
- **キャラクターは全てCSS/SVG。** 既存IPを一切参照しない完全オリジナル。
- **手アイコンは「太い縁取り＋塗り＋しわ線」の3パス**で描画。図形ごとに縁取ると肉球に見えるため。
- **rAFフォールバック。** 一部WebView/省電力環境で`requestAnimationFrame`が発火しないため、
  500ms以内に描画が始まらなければタイマー描画へ退避する。
- **決着中は盤面を暗転**し、HUDだけを前面に残す。連勝数は増える瞬間こそ読ませる。

## 検証済み

375 / 390 / 430px で横溢れなし。タップ領域136px。コンソールエラーなし。
自動プレイでタイトル→複数ステージ→敗北→リザルト→再挑戦まで通し確認済み。

## デバッグ

`window.JR` から `setSpeed(x)`（演出の時間倍率）、`applyStage()`、`render()` を利用できる。
