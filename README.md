# JANKEN RUSH — prototype v0.2

ジャンケンの皮をかぶった「期待感エンジン」。依存ライブラリ・画像・音源ファイルはゼロ。

```bash
python3 -c "import os
from http.server import SimpleHTTPRequestHandler, ThreadingHTTPServer
os.chdir('.')
class H(SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cache-Control','no-store, max-age=0')
        SimpleHTTPRequestHandler.end_headers(self)
ThreadingHTTPServer(('127.0.0.1',5177),H).serve_forever()"
```

ESモジュール構成のため `file://` では動かない。ローカルサーバー経由で開くこと。

---

## 最重要原則

> **演出は結果を最高に見せる。しかし、プレイヤーの選択を無意味にはしない。**

v0.1 は勝敗を先に決めて演出から逆算していた。これはプレイヤーを欺く設計なので v0.2 で廃止した。
現在、勝敗を決めるコードは `src/core.js` の `judge(playerHand, enemyHand)` ただ一箇所にしかない。

## ファイル構成

| ファイル | 責務 | DOMに触るか |
|---|---|---|
| `src/core.js` | ルール・敵AI・演出プランナー・ステージ定義・SHOWCASE台本 | **触らない** |
| `src/view.js` | Canvas描画・粒子・WebAudio合成音・DOM演出 | 触る |
| `src/game.js` | 状態機械・モード制御・ラウンド進行 | 繋ぐだけ |
| `src/boot.js` | モジュールキャッシュ回避のためのローダ | — |
| `src/styles.css` | 全スタイル | — |
| `index.html` | マークアップのみ | — |

`core.js` は `window` にも `document` にも触れない。勝敗ロジックを演出コードから物理的に隔離するための境界。

## 3つのモード

| | FAIR PLAY | 訓練戦 | SHOWCASE |
|---|---|---|---|
| 勝敗の決め方 | 敵AIが独立に手を決定 → `judge()` | 同左（完全に公平） | **台本が敵の手を逆算** |
| 敵の手 | 見えない | **選ぶ前に見える** | 見えない |
| 敗北時 | 連勝終了 | 終了しない（練習継続） | 台本どおり進む |
| BEST更新 | する | しない | しない |
| 終了条件 | 敗北（復活しなければ） | 決着2回 | 台本8手 |
| 用途 | 通常プレイ | 初回オンボーディング | デモ・プレゼン・デバッグ |

SHOWCASE だけが `showcaseEnemyHand()` を呼ぶ。この関数は `core.js` 内で
「SHOWCASE専用。FAIR PLAY からは参照されない」と明示している。

## 敵AI

ラウンド開始時（プレイヤーが手を選ぶ**前**）に、敵は次の順で自分の手を確定させる。以後その値は変わらない。

```
アーキタイプの方針 → 内部状態で補正 → 分布を正規化 → サンプリングして手を確定 → セリフを生成
```

| 型 | 方針 |
|---|---|
| ゴリ押し型 | グー60 / チョキ20 / パー20。連敗するとグー率が最大+25pt上昇 |
| フェイント型 | 宣言した手20 / **宣言に勝つ手50** / 残り30。素直に出すのは20% |
| コピー型 | 直前のプレイヤーの手45 / それに勝つ手35 / ランダム20 |
| 学習型AI | 直近10手を集計。最頻手に勝つ手55 / 次点に勝つ手20 / ランダム25 |
| 狂乱型 | 完全ランダム。読みは通用しない |

**内部状態**（攻撃的・警戒・混乱・フェイント・コピー準備・弱気・覚醒）が分布を補正し、
セリフ・目線の色・オーラ・構えを生成する。状態ごとに `readability`（セリフが本音を漏らす確率）が
異なるため、**読み違いが必ず起きる**。フェイント型のセリフは常に罠。

セリフが本当だったかは、結果が出た**後**に「読み的中／読み外し」として正直に表示する。

## 読みが勝敗に影響する証拠（20,000回 × 5型 × 3戦略）

決着勝率（あいこを除いた勝率）：

| 敵 | ランダム | セリフを素直に読む | 型を理解した読み |
|---|---:|---:|---:|
| ゴリ押し型 | 50.0% | 67.1% | 67.2% |
| フェイント型 | 49.7% | **41.6%** | **69.7%** |
| コピー型 | 49.9% | 67.2% | 66.8% |
| 学習型AI | 49.5% | 62.2% | 61.7% |
| 狂乱型 | 49.5% | 52.6% | 52.5% |

- ランダムプレイヤーは全型で厳密に50%。分布に偏りは無い。
- フェイント型は**素直に読むとランダムより弱くなる（41.6%）**。二段読みで69.7%。
  「読み合い」が数値として成立している。
- 狂乱型は読んでも52%。読みが効かない相手を意図的に置いている。

## 連勝分布（20,000ラン）

| 戦略 | 平均連勝 | 兆し(1) | 擬似連(2) | RUSH(3) | 神域(5) | 超神域(7) |
|---|---:|---:|---:|---:|---:|---:|
| ランダム | 1.03 | 50.6% | 25.8% | 13.1% | 3.5% | 0.9% |
| 素直に読む | 1.40 | 56.1% | 33.5% | 20.7% | 7.1% | 2.6% |
| 型を理解 | 1.72 | 61.2% | 39.3% | 25.9% | **10.6%** | **4.3%** |

公平判定では完璧に読んでも決着勝率の上限が約70%なので、連勝は伸びにくい。
ステージ閾値はこの実測分布に合わせて `[0,1,2,3,5,7]` に設定した（SHOWCASEは台本用に別値）。

## 期待度と復活の意味

期待度は「勝率の予告」ではなく「**何か特別な展開が起きる予告**」。

| 期待度 | 意味 |
|---|---|
| 金 + 勝利 | 役物 or カットイン勝利 |
| 金 + あいこ | カットイン付き擬似連 |
| 金 + 敗北 | 高確率で復活 |
| 虹 | プレミア体験確定（フリーズ含む） |

**復活はジャンケンの結果を覆さない。** 「負けたが連勝記録は途切れない」という
独立したゲームルールとして実装している。演出の劇的さを保ちながら、勝敗判定を曲げない。
実測発生率は敗北の約4〜5%。

## あいこ（擬似連）

あいこは引き分けではなく、期待値が積み上がる主役。低段階は高速、高段階だけ特別にする。

| 回数 | 表示 | 長さ |
|---:|---|---:|
| 1 | 激突 | 0.55s |
| 2 | まだ終わらない | 0.88s |
| 3 | 限界突破 | 1.20s |
| 4 | 世界停止 | 1.70s |
| 5+ | 神手決戦（虹爆発＋確定音） | 2.20s |

あいこ中はプレイヤーが**毎回選び直す**。敵も毎回手を引き直す。約30%のラウンドであいこが発生する。

## 検証結果（v0.2）

- **100戦耐久**: 101戦 / 163ターン / 53ラン / 演出中の割り込み再スタート3回
  → エラー0、UI残骸0、白フラッシュ残存0、暗転未解除0、擬似連持ち越し0、二重進行0
- **DOMノード数**: 217 で完全一定（リーク無し）
- **処理速度**: 1戦あたり 669ms（最初の20戦）→ 654ms（全体平均）。劣化なし
- **描画負荷**: 最重演出460粒子で 0.303ms/frame（60fps予算の約55倍の余裕）。EFFECT LOW で 0.064ms
- **メモリ**: 2MB
- **レイアウト**: 375×667 / 375×812 / 390×844 / 430×932 / 430×667 で
  重なり・縦横あふれ・タップ領域不足なし。手ボタン109〜133px
- **構文**: `node --input-type=module --check` 全ファイル通過

## デバッグ

`window.JR` から `build` / `state()` / `residue()` / `pick(hand)` / `setSpeed(x)` /
`startFair()` / `startShowcase()` / `startTraining()` を利用できる。
`residue()` は演出の残骸（暗転・フラッシュ・粒子数・DOM数）を一括で返す耐久試験用。

## 既知の技術的負債

- **音は未検証**。この開発環境では音を鳴らして確認できない。実機での確認が必要。
- **BGM無し**。連勝が伸びてもBPMが上がらず、身体が加速しない。次の最大の伸びしろ。
- `boot.js` が毎回ユニークURLでモジュールを読むため、ブラウザキャッシュが一切効かない。
  開発中は正しいが、公開時はビルド時のハッシュ付きURLへ置き換えるべき。
- あいこの連鎖に上限が無い（実測で10連鎖を観測）。5回目以降は同じ「神手決戦」を繰り返す。
- `#preview`（訓練戦の手表示）は arena 上端固定。より小さい端末が来た場合は再確認が必要。
